# AI Job Hunter

AI Job Hunter — автоматизированная система поиска и анализа вакансий Python Developer в Telegram с использованием AI.

Приложение отслеживает Telegram-группы и каналы, находит публикации о вакансиях, анализирует их содержание, оценивает соответствие требованиям кандидата и генерирует персонализированные сопроводительные письма.

Основная задача проекта — автоматизировать рутинную часть поиска работы и предоставить кандидату структурированную информацию о подходящих вакансиях.

---

## Возможности

### 1. Автоматический поиск источников

- Анализ Telegram-групп и каналов, доступных авторизованному аккаунту.
- Автоматическое обнаружение источников с вакансиями.
- Определение источников, публикующих вакансии Python Developer.
- Сохранение найденных источников в SQLite.
- Периодическое обновление списка источников.

> Приложение не вступает в новые группы автоматически. Оно анализирует только те группы и каналы, которые уже доступны Telegram-аккаунту.

### 2. Мониторинг вакансий

- Отслеживание новых сообщений в выбранных источниках.
- Поиск вакансий Python Developer.
- Извлечение информации из публикаций.
- Фильтрация нерелевантных сообщений.
- Защита от повторной обработки вакансий.

### 3. AI-анализ вакансий

Каждая найденная вакансия анализируется с использованием AI.

Система извлекает:

- Название должности.
- Название компании.
- Описание вакансии.
- Требуемые навыки.
- Требуемый опыт.
- Формат работы.
- Уровень заработной платы, если указан.
- Контактную информацию и ссылку на вакансию.

### 4. Сопоставление с профилем кандидата

Система сравнивает требования вакансии с профилем кандидата и оценивает:

- Соответствие технических навыков.
- Соответствие опыта работы.
- Соответствие профессионального направления.
- Общую релевантность вакансии.

По результатам формируется оценка соответствия (Match Score).

### 5. Генерация сопроводительных писем

Для подходящих вакансий AI:

1. Анализирует описание вакансии.
2. Изучает профиль кандидата.
3. Определяет наиболее релевантные навыки и опыт.
4. Генерирует персонализированное сопроводительное письмо на русском языке.
5. Проверяет письмо на соответствие профилю кандидата и требованиям вакансии.

Система не должна придумывать несуществующий опыт, навыки или достижения кандидата.

### 6. Уведомления в Telegram

После обработки подходящей вакансии приложение отправляет сообщение в настроенный Telegram-чат.

Уведомление содержит:

- Название вакансии.
- Компанию.
- Ссылку на оригинальную публикацию.
- Основную информацию о вакансии.
- Оценку соответствия кандидату.
- Сопроводительное письмо.

**Важно:** приложение не отправляет отклики работодателям и не отправляет письма по электронной почте. Все результаты предназначены для просмотра кандидатом в Telegram.

### 7. Письмо под любую вакансию по запросу

Если нашёл вакансию сам, просто перешли её боту в личные сообщения. Поддерживаются три формата:

| Что отправить | Что произойдёт |
|---|---|
| Текст вакансии | Бот разберёт её и напишет письмо |
| Ссылка | Бот откроет страницу, достанет текст вакансии и напишет письмо |
| Скриншот или фото (можно несколько сразу) | Vision-модель распознаёт текст, дальше как обычно |

В ответ приходят три сообщения: краткая сводка по вакансии с оценкой совпадения, само письмо (отдельным сообщением, чтобы его было удобно скопировать) и результат проверки письма на неподтверждённые резюме утверждения.

Особенности:

- Фильтр по минимальному баллу здесь не применяется: письмо создаётся для любой присланной вакансии.
- Письмо пишется на языке вакансии (русский или английский).
- Вакансия сохраняется в БД и помечается отправленной, поэтому Listener не пришлёт её повторно.
- Для `hh.ru` используется открытый API сайта, для остальных сайтов читается JSON-LD `JobPosting` или текст страницы.
- Страницы, которые подгружаются скриптами или закрыты авторизацией (например, часть LinkedIn и закрытые Telegram-посты), прочитать не получится. Бот попросит прислать текст или скриншот.
- Бот отвечает только пользователю из `TELEGRAM_ADMIN_USER_ID` и только в личном чате.

Команда `/vacancy` необязательна: она просто подсказывает, что бот ждёт вакансию. Любое сообщение с вакансией (текст, ссылка, скриншот) обрабатывается и без неё.

Для скриншотов нужна модель с поддержкой изображений: она задаётся переменной `OPENROUTER_VISION_MODEL`. Модель по умолчанию для текста (`OPENROUTER_MODEL`) изображения может не поддерживать.

### 8. Резюме и профиль прямо в боте

Резюме и предпочтения можно менять в Telegram, без правки файлов на сервере.

**Резюме.** Команда `/resume`, затем PDF-файл (до 10 МБ, с текстовым слоем). Бот прочитает текст, покажет его начало для проверки и будет использовать это резюме для всех писем. Сканы и PDF без текста не поддерживаются.

**Профиль.** Команда `/profile` показывает текущие данные и кнопки для редактирования полей:

| Поле | Как вводится |
|---|---|
| `target_roles` Желаемые роли | Список: добавить, заменить или очистить |
| `experience_years` Опыт (лет) | Число, например `5` |
| `skills` Навыки | Список: добавить, заменить или очистить |
| `preferred_work_formats` Формат работы | Кнопки: удалённо, гибрид, офис |
| `preferred_employment_types` Тип занятости | Кнопки: полная, частичная, проектная, стажировка |
| `minimum_salary` Минимальная зарплата | Число: `150000` или `150к` |
| `languages` Языки | Список, например `Русский — родной, English — B2` |
| `preferred_locations` Локации | Список |
| `additional_information` Дополнительно | Свободный текст до 1000 символов |

Списки вводятся через запятую или с новой строки. Повторы (без учёта регистра) отбрасываются.

Загруженные резюме и профиль хранятся в SQLite и имеют приоритет над файлами `data/resume.pdf` и `data/candidate_profile.json`. Файлы остаются запасным вариантом, пока в боте ничего не загружено. Изменения применяются сразу и для бота, и для Listener, перезапуск не нужен.

Команда `/cancel` отменяет текущее действие. Если бот ждёт ввод и ты ничего не прислал, ожидание сбрасывается через 15 минут.

### 9. Первая настройка: без неё ничего не запускается

После установки бот работает, а всё остальное закрыто, пока ты не пройдёшь настройку:

- **Listener** не подключается к Telegram и не ищет источники, он ждёт и раз в 30 секунд проверяет, закончена ли настройка. В логах будет предупреждение «Настройка не завершена, Listener ожидает».
- **Обработка вакансий и письма** не выполняются, включая `/vacancy` и любые присланные вакансии. Вместо этого бот предлагает продолжить настройку.
- **Всегда доступны:** `/start`, `/setup`, `/resume`, `/profile`, `/help`, `/cancel`, а также `/sources`, `/enable` и `/disable`.

**Что нужно сделать.** Открой бота и нажми `/start` (или `/setup`). Бот проведёт по 10 шагам:

1. Загрузить резюме (PDF).
2. Ответить на 9 вопросов профиля: `target_roles`, `experience_years`, `skills`, `preferred_work_formats`, `preferred_employment_types`, `minimum_salary`, `languages`, `preferred_locations`, `additional_information`.

**Что считается заполненным:**

- Резюме загружено через бота. Файл `data/resume.pdf` на сервере не засчитывается.
- Каждое поле подтверждено явным ответом.
- Обязательные поля не могут быть пустыми: роли, навыки, формат работы и тип занятости.
- Остальные можно явно пропустить кнопкой «Не важно / нет»: зарплату, языки, локации и дополнительную информацию.
- Опыт требует числа, `0` тоже считается ответом.
- Если в `data/candidate_profile.json` уже есть данные, бот покажет их на шаге, и их можно подтвердить кнопкой «Оставить как есть». Сами по себе они не засчитываются.

Когда все шаги пройдены, бот пишет «Настройка завершена». Listener запускается сам в течение 30 секунд, перезапуск не нужен. Если позже очистить обязательное поле или заменить резюме на некорректное, обработка снова останавливается до исправления.

Если бот перезапустили посреди настройки, нажми `/setup`: заполненные шаги сохранены.

```bash
cd ai_job_hunter
```

## 3. Настройка переменных окружения

Создать `.env` на основе шаблона:

```bash
cp .env.example .env
```

Открыть `.env` и заполнить необходимые параметры.

Пример:

```dotenv
# OPENROUTER
OPENROUTER_API_KEY=your_openrouter_api_key
OPENROUTER_MODEL=nvidia/nemotron-3.5-lightning:free
OPENROUTER_VISION_MODEL=google/gemini-2.5-flash

# LANGCHAIN (optional)
LANGCHAIN_TRACING_V2=false
LANGCHAIN_API_KEY=
LANGCHAIN_PROJECT=AI-Job-Hunter

# TELEGRAM BOT
TELEGRAM_BOT_TOKEN=your_telegram_bot_token
TELEGRAM_CHAT_ID=your_telegram_chat_id
TELEGRAM_ADMIN_USER_ID=your_telegram_user_id

# SQLITE
DATABASE_PATH=data/job_hunter.db

# TELETHON
TELEGRAM_API_ID=your_telegram_api_id
TELEGRAM_API_HASH=your_telegram_api_hash
TELEGRAM_SESSION_PATH=credentials/telegram_user
```

### Где получить Telegram credentials

**Telegram Bot Token**

1. Открыть Telegram.
2. Найти @BotFather.
3. Создать бота командой `/newbot`.
4. Скопировать токен и записать его в `TELEGRAM_BOT_TOKEN`.

**Telegram API ID и API Hash**

1. Перейти на https://my.telegram.org.
2. Авторизоваться в Telegram.
3. Открыть раздел API Development Tools.
4. Создать приложение.
5. Скопировать `api_id` и `api_hash`.

**TELEGRAM_CHAT_ID**

ID Telegram-чата, в который приложение будет отправлять уведомления о вакансиях.

**TELEGRAM_ADMIN_USER_ID**

Telegram ID пользователя, которому разрешено управлять источниками.

> Не публикуйте `.env`, API-ключи, токены и файлы Telegram-сессии в Git. Убедитесь, что они добавлены в `.gitignore`.

## 5. Сборка Docker-образа

В корневой директории проекта выполнить:

```bash
make build
```

```bash
docker compose -f docker/app/docker-compose.yml build
```

## 6. Первичная авторизация Telethon

Для мониторинга Telegram используется пользовательский аккаунт, а не Telegram-бот.

Поэтому перед первым запуском необходимо авторизовать Telethon.

Выполнить:

```bash
make auth-telegram
```

В терминале появится запрос:

```text
Введите номер телефона в международном формате:
```

Ввести номер:

```text
+79991234567
```

Далее Telegram отправит код подтверждения.

Ввести полученный код:

```text
Введите код подтверждения из Telegram:
```

Если включена двухфакторная аутентификация, приложение дополнительно запросит пароль Telegram.

При успешной авторизации появится сообщение:

```text
Авторизация успешно выполнена!
Аккаунт: your_username
Сессия сохранена: /app/credentials/telegram_user
```

Сессия сохраняется в Docker volume `telegram_credentials`.

**Важно:**

- Авторизацию достаточно выполнить один раз.
- Не удаляйте Docker volume `telegram_credentials`.
- Не передавайте файл сессии третьим лицам.
- При повторных запусках номер телефона и код вводить не требуется.

## Telegram Source Manager

Source Manager предназначен для управления Telegram-источниками.

В зависимости от реализации доступны команды:

| Команда | Описание |
|---|---|
| `/start` | Запуск; при первом запуске начинает настройку |
| `/setup` | Пошаговая настройка: резюме и профиль |
| `/help` | Справка |
| `/vacancy` | Прислать вакансию, чтобы получить письмо |
| `/resume` | Загрузить своё резюме (PDF) |
| `/profile` | Посмотреть и изменить профиль |
| `/cancel` | Отменить текущее действие |
| `/sources` | Просмотр источников |
| `/enable ID` | Активация источника |
| `/disable ID` | Деактивация источника |

Управление доступно только пользователю, указанному в `TELEGRAM_ADMIN_USER_ID`.

Кроме команд бот принимает вакансии (текст, ссылка, скриншот) и отвечает сопроводительным письмом, см. раздел «Письмо под любую вакансию по запросу».

```text
                    |
                    v
              Match Score
                    |
                    v
          Cover Letter Generator
                    |
                    v
             Cover Letter Review
                    |
                    v
            Telegram Notification
                    |
                    v
             Candidate Reviews
```

1. Listener подключается к Telegram.
2. Находит доступные группы и каналы.
3. Определяет источники с Python-вакансиями.
4. Отслеживает новые публикации.
5. Передаёт сообщения в Vacancy Pipeline.
6. AI анализирует и структурирует вакансию.
7. Matcher оценивает соответствие профилю кандидата.
8. Для подходящих вакансий генерируется сопроводительное письмо.
9. Reviewer проверяет его содержание.
10. Результат отправляется в Telegram.

# Хранение данных

Для хранения информации используется SQLite.

Основной файл базы данных внутри Docker:

```text
/app/db/job_hunter.db
```

Docker volume:

```text
app_data
```

Telegram-сессия хранится отдельно:

```text
/app/credentials/telegram_user
```

Docker volume:

```text
telegram_credentials
```

Данные кандидата и резюме подключаются из локальной директории `data/`.

**Важно:** `docker compose down` не удаляет именованные volumes. Однако команда `docker compose down -v` удалит volumes и приведёт к потере базы данных и Telegram-сессии.

Не используйте `-v`, если не собираетесь намеренно сбрасывать данные.

# Решение проблем

## Telethon просит номер телефона при запуске Listener

Ошибка:

```text
EOFError: EOF when reading a line
```

Причина: пользовательская Telegram-сессия отсутствует или не авторизована.

Решение:

```bash
make auth-telegram
```

После успешной авторизации:

```bash
make up
```

Если проблема повторяется, проверьте наличие volume:

```bash
docker volume ls
```

## Telegram Bot получает ConnectTimeout

Ошибка:

```text
httpx.ConnectTimeout
telegram.error.TimedOut
```

Причина: контейнер не может установить соединение с Telegram Bot API.

Проверить доступность API:

```bash
docker compose -f docker/app/docker-compose.yml exec bot \
python -c "import socket; print(socket.create_connection(('api.telegram.org', 443), timeout=10))"
```

Если возникает timeout, проверьте:

- Интернет-соединение.
- DNS.
- Firewall.
- Сетевые ограничения Docker.
- Необходимость использования прокси для доступа к Telegram.

## Listener не находит источники

Проверить:

```bash
make logs
```

Убедиться, что Telegram-аккаунт авторизован и имеет доступ к группам и каналам.

Автоматический поиск не может обнаружить закрытые группы, в которых аккаунт не состоит.

## Перезапуск приложения

```bash
make restart
```

## Полная остановка

```bash
make down
```

# Ограничения

- Поиск источников выполняется только среди групп и каналов, доступных авторизованному Telegram-аккаунту.
- Автоматическое обнаружение источников основано на анализе названий и содержимого публикаций и может требовать ручной корректировки.
- Качество анализа и сопроводительных писем зависит от выбранной AI-модели.
- AI может ошибаться, поэтому перед откликом необходимо самостоятельно проверить вакансию и письмо.
- Приложение не отправляет отклики работодателям автоматически.
